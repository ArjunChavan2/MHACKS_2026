# Review

- Each new call session stores exact approved facts and saved preference version. New contact checks current constraints/evidence and latest unused plan. Case-owned SID is generated by the service; browsers cannot submit arbitrary Twilio IDs.
- An uncertain provider start is terminal; automatic retry does not occur. End/takeover still work after a contact hold. Transfer status means requested, never successful by assumption.
- Administrative proposal results cannot authorize agreements/payments. A forty-second timeout declines. Representation consent is separately bound to its request and expiry.
- Rehearsal controls never use provider functions. All synthetic content stays labeled, including original offer turns and outcome views.
- Outcome notes/proposed dates are persisted independently of deterministic savings and case evidence. Written proof still uses existing confirmation/verification flows.
- Denials must be confirmed before policy evaluation. All record evidence remains verbatim and cited; unsupported policies draft nothing. Corrected confirmed values survive reload. The demo policy is prominently labeled synthetic.
- No new secret values or real patient data are present. No agent/provider configuration was changed externally.
- Live calling remains disabled until a scoped agent and runtime safeguards are deployed. Process-local serialization is insufficient for multiple concurrent server instances; case-ID capability access is the existing demo model. See deployment documentation.
- Parser latency is still tracked separately in issue #7; this change does not optimize extraction time.
