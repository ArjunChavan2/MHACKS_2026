# neon-setup — IMPLEMENTATION

Branch `Neon`. Goal: make Neon the real database (SPEC.md §4.6, §5.1, §6 MVP 0 "Neon keys
verified"). No PLAN.md; the user asked directly. Audit against SPEC.md §4.6 and §5.

## What changed

- `db/schema.ts`: added `approvals` and `deadlines` (MVP 0 schema list, unused until MVP 2) and a
  private `files` table (base64 text) so uploaded and sample files survive restarts and Vercel
  function instances. Before this, files lived in process memory, so the confirm-screen preview
  (`/api/documents/[id]/file`) would 404 on Vercel even with Neon set.
- `db/migrations/0000_init.sql` (+ `meta/`): first committed migration, generated by Drizzle Kit.
- `lib/cases/store.ts`: `putFile`/`getFile` moved onto `CaseStore` (async); `neonStore` is now a
  thin wrapper over `pgStore(db)`, which takes any Drizzle Postgres database (Neon HTTP in the app,
  PGlite in tests). `getDocument` maps columns explicitly instead of casting the row.
- `lib/cases/service.ts`, `app/api/documents/[id]/file/route.ts`: use the async store file API.
- `drizzle.config.ts`: loads `.env.local`, writes to `db/migrations`, prefers `DATABASE_URL_UNPOOLED`.
- `scripts/env.ts`, `scripts/db-migrate.ts`, `scripts/db-check.ts`; npm scripts `db:generate`,
  `db:migrate`, `db:check`, `db:studio`.
- `tests/db/store.test.ts`: applies the real migrations to PGlite and runs `pgStore` plus the case
  service (sample bill + EOB → confirm → audit twice) against it. devDependency `@electric-sql/pglite`.
- `.env.example`, SPEC.md §4.6 (file storage decision, marked *Open* to revisit).

## Known limits

- Replacing findings is delete-then-insert, not atomic (the Neon HTTP driver has no transactions);
  re-running the audit repairs it.
- Vercel limits function request bodies to about 4.5 MB, below the 15 MB upload cap in
  `app/api/documents/route.ts`; large photos will fail on Vercel before reaching Neon.
- An upload whose extraction fails leaves an orphan `files` row (same as before, now persistent).
